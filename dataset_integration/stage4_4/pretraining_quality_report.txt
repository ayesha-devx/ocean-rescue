B. Scientific Role of Background Images:
  In underwater ROV surveys, vast stretches of seabed contain no human debris,
  displaying only natural substrate, kelp, sea urchins, fish, or parts of the ROV.
  Excluding empty images causes object detection models to suffer from catastrophic
  false-positive rates when deployed in real waters. Modern object detection best
  practices (e.g. Ultralytics guidelines) recommend 10% to 20% background images.
  The OceanRescue split naturally achieves a balanced 19.2% background ratio.


3. MODEL FORMAT SELECTION & TRADE-OFF ANALYSIS
--------------------------------------------------------------------------------
Why Bounding Boxes Alone Are Insufficient for Nets & Ropes:
- Fishing nets and ropes (ALDFG) are non-rigid, elongated, deformable objects.
- A long diagonal rope across a 1920x1080 frame produces a bounding box covering
  nearly the entire screen, where >85% of enclosed pixels are background seabed!
- Bounding-box-only models (standard YOLO/Faster R-CNN) struggle with severe IOU
  penalties and false overlapping detections on tangled netting.
- Instance Segmentation (predicting exact pixel contours) is mandatory.

Format Comparison:
  Format            Mask Support  Edge Inference  Annotation File Layout
  -----------------------------------------------------------------------
  COCO JSON         Polygon / RLE Moderate (heavy) Single centralized JSON
  YOLOv8-seg        Norm Polygon  Ultra-Fast (ROV) Flat .txt file per image
  Pascal VOC XML    None (Bbox)   Deprecated      One XML per image
  -----------------------------------------------------------------------

Selected Format:
- Primary Training & Edge Deployment: YOLOv8-seg / YOLOv11-seg format.
- Canonical Benchmark & Archival    : COCO JSON (already generated in Stage 4.3).


4. COORDINATE CONVERSION & BOUNDARY CLAMPING AUDIT
--------------------------------------------------------------------------------
A. Coordinate Mathematical Conversion:
  - Bbox Conversion:
      x_center = (x_min + w / 2.0) / img_width
      y_center = (y_min + h / 2.0) / img_height
      w_norm   = w / img_width
      h_norm   = h / img_height
  - Polygon Conversion:
      x_norm_i = x_pixel_i / img_width
      y_norm_i = y_pixel_i / img_height

B. Discovery of TrashCan Edge Overshoot:
  - Inspection of 22,659 annotations revealed 86 bounding boxes and 2,339 polygon
    vertices where raw coordinates slightly exceeded image boundaries by <= 1.0 px
    (e.g., coordinate 271.0 px on a 270 px high image; 480.99 px on 480 px width).
  - Cause: Contour simplification (`measure.find_contours`) during the original
    TrashCan dataset creation produced floating-point vertices on pixel boundaries.
  - Failure Risk: Unclamped coordinates (> 1.0) trigger fatal assertion errors
    during YOLO training dataset ingestion.

C. Clamping Protocol:
  - Formula:
      x_clamped = min(max(x, 0.0), float(img_width))
      y_clamped = min(max(y, 0.0), float(img_height))
  - Verification Result:
    - Raw out-of-bounds annotations     : 86 bboxes, 2,339 polygon vertices
    - Clamped out-of-bounds annotations : 0 [PASS]
    - In-bounds reconstruction error    : < 1.7e-13 px (machine precision) [PASS]
